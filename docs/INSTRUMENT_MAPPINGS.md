# Сопоставление инструментов PerpDexList

Источник: [arbitrage](https://perpdexlist.com/arbitrage), публичный
[/api/dashboard/markets-v2](https://perpdexlist.com/api/dashboard/markets-v2).
Снимок хранится в `src/instrument_mappings.json`: 740 рынков семи подключённых
perp-площадок, 74 записи с переименованием. В файле есть время выгрузки,
исходный биржевой тикер, класс актива, общий тикер и множитель базового количества.
Часть записей может отсутствовать в актуальном API площадки: при запуске
используются только реально доступные адаптеру рынки.

Дополнение 27 сентября 2026: добавлены 569 USDT-рынков Aster. Исходные 740 записей
других площадок сохранены; дата отдельной выгрузки находится в `venue_imports.aster`.
Множители с числовым префиксом (например, 1000000) поддерживаются импортёром также.

| --- | --- | --- |
| XAU | Polymarket GOLD; Extended XAU; Lighter RH XAU | 1 |
| PAXG | Hyperliquid, Extended, Hibachi PAXG | 1 |
| XAUT | Nado, Extended XAUT | 1 |
| PEPE | Hyperliquid/Nado kPEPE; Polymarket KPEPE; Extended 1000PEPE | 1000 |
| WTIOIL | Extended/Nado WTI; Polymarket WTIOIL | 1 |
| US100 | Extended TECH100M; Polymarket NAS100 | 1 |
| NATGAS | Extended XNG | 1 |
| OPENAI | Entropy OAI | 1 |

| AAPL и другие акции | Extended AAPL_24_5 и аналогичные суффиксы | 1 |

В PerpDexList [XAU](https://perpdexlist.com/markets/rwa/XAU), PAXG и XAUT —
разные группы. Они не объединяются в один «gold». У торговых площадок могут
различаться торговые часы, источники индексов и условия контрактов; сопоставление
источника не отменяет проверок базиса и ликвидности.

## Единицы и исполнение

`NormalizedAdapter` оборачивает подключённый адаптер. Исходное API продолжает
получать родные символы. Сканер и paper-исполнение работают с общим базовым активом:

- цена делится на `base_units`;
- количество умножается на `base_units`;
- денежная стоимость сохраняется;
- ставки funding и процентные комиссии не масштабируются;
- funding-индексы Nado в деньгах на единицу делятся на `base_units`.

Пример: 100 контрактных единиц kPEPE по $0,004 соответствуют 100 000 PEPE по
$0,000004; стоимость обеих записей $0,40. Paper-ордер на 100 000 PEPE хеджирует
100 000 PEPE на другой площадке, а не 100 000 пакетов по тысяче токенов.
Множитель 1000 применяется только к явным `k`/`K`/`1000` обозначениям, когда
источник подтверждает соответствующий общий актив; цены проверены публичными API.

При двух исходных рынках одного адаптера с одним общим тикером вся неоднозначная
группа исключается; первый попавшийся рынок не выбирается. Неизвестные источнику
символы сохраняют прежнее точное сопоставление, без эвристического удаления букв.
Live-исполнение нормализованных инструментов заблокировано.

Старые позиции с исходными названиями (например, kPEPE) продолжают читаться в
прежних единицах. Проверка дублирующих позиций и cooldown учитывают исходные
псевдонимы. История funding по новым общим тикерам должна накопиться заново;
старые исторические записи не переименовываются.

## Спот

В используемом публичном feed PerpDexList нет спотовых рынков. Поэтому новые
соответствия для спота не выдумываются. Нормализация perp-ноги расширяет уже
существующее сравнение с одноимённым спотом, например PEPE и акциями.
UBTC/BTC, UETH/ETH, XAUT0/XAUT и XAUM/XAU этой выгрузкой не подтверждены и
автоматически не объединены. Идентичность спотового токена и его обёртки требует
отдельного реестра контрактов/эмитентов.

## Обновление

Бот использует локальный снимок и не зависит от доступности PerpDexList во время
торговли. Для обновления сначала выгрузить новый файл, сравнить изменения и
проверить единицы новых инструментов:

```powershell
python scripts/import_perpdexlist.py --output data/instrument_mappings.candidate.json
```

После проверки заменить `src/instrument_mappings.json` и перезапустить бот.
Нельзя менять множители открытых канонических позиций без миграции их состояния.
При запуске `instruments.mapped` показывает число рынков, псевдонимов и неоднозначные
группы. Новые рынки подхватываются при следующем запуске.

При проверке дополнительно исправлен Polymarket: ответ `/tickers` фильтруется по
`instrument_id`, даже если сервер игнорирует параметр запроса. Чужой стакан с
несовпадающим `instrument_id` отклоняется. Это устраняет использование цены и
funding первого рынка для другого инструмента.
