# Риск-менеджмент

## Параметры (все в .env)

### Размер позиции

| Параметр | Дефолт | Описание |
|----------|--------|----------|
| `MAX_POSITION_PCT` | `0.10` | % от минимального баланса между биржами на одну ногу |
| `LEVERAGE` | `1.0` | Кредитное плечо. Увеличивает размер позиции, но и риск ликвидации |
| `MAX_OPEN_PAIRS` | `5` | Максимальное число одновременных арбитражных пар |

**Верхний предел**: `notional = min(balance_A, balance_B) × MAX_POSITION_PCT × LEVERAGE`.
Перед входом бот уменьшает размер до максимального значения, которое проходит
проверку глубины двух стаканов, проскальзывания и окупаемости. Если даже
`MIN_POSITION_USD` не проходит, вход отклоняется. `MAX_DAILY_LOSS_USD` запрещает
новые входы после достижения дневного реализованного убытка; открытые позиции
этим ограничением принудительно не закрываются.

Пример: баланс $50k на каждой бирже, MAX_POSITION_PCT=0.10, LEVERAGE=2.0:
`notional = $50,000 × 0.10 × 2.0 = $10,000` на ногу.

### Пороги входа

| Параметр | Дефолт | Описание |
|----------|--------|----------|
| `MIN_FUNDING_SPREAD` | `0.0001` | Минимальный почасовой спред для открытия |
| `MIN_NET_PNL_AFTER_FEES` | `0.00005` | Минимальная ожидаемая доходность после затрат |
| `EXPECTED_HOLD_HOURS` | `8` | Горизонт оценки дохода от funding |
| `MAX_SLIPPAGE` | `0.001` | Макс. допустимое проскальзывание при входе (0.1%) |
| `SLIPPAGE_CHECK_NOTIONAL` | `10000` | Размер в USD для оценки proскальзывания по стакану |

---

### Выход

| Параметр | Дефолт | Описание |
|----------|--------|----------|
| `EXIT_FUNDING_SPREAD` | `0.00005` | Закрыть, когда почасовой спред упал ниже значения |
| `MAX_HOLD_HOURS` | `72` | Принудительное закрытие через N часов независимо от спреда |

**Рекомендация**: `EXIT_FUNDING_SPREAD` = `MIN_FUNDING_SPREAD / 2`.

---

### Защита от потерь

| Параметр | Дефолт | Описание |
|----------|--------|----------|
| `DELTA_STOP_LOSS_PCT` | `0.02` | Закрыть если цены ног разошлись более чем на 2% |
| `CIRCUIT_BREAKER_FAILURES` | `3` | Пауза после N последовательных ошибок ордеров |
| `CIRCUIT_BREAKER_BASE_DELAY_SEC` | `30` | Начальная пауза circuit breaker (удваивается: 30s → 60s → 120s...) |
| `FUNDING_SPIKE_LOOKBACK_MIN` | `60` | Не входить если ставка была аномальной последние N минут |

---

### Shutdown

| Параметр | Дефолт | Описание |
|----------|--------|----------|
| `SHUTDOWN_MODE` | `close_positions` | `close_positions` — немедленно закрыть всё; `save_state` — сохранить и выйти |
| `SHUTDOWN_TIMEOUT_SEC` | `30` | Таймаут ожидания закрытия позиций при shutdown |

## Рекомендации по настройке

### Консервативный старт (рекомендуется)
```
MAX_POSITION_PCT=0.05    # 5% от баланса
LEVERAGE=1.0             # без плеча
MAX_OPEN_PAIRS=2         # максимум 2 пары
MIN_FUNDING_SPREAD=0.0002  # в 2 раза выше дефолта
```

### После 2+ недель paper trading
```
MAX_POSITION_PCT=0.10
LEVERAGE=1.5
MAX_OPEN_PAIRS=5
MIN_FUNDING_SPREAD=0.0001
```

### Агрессивный (только с опытом)
```
MAX_POSITION_PCT=0.20
LEVERAGE=2.0
MAX_OPEN_PAIRS=10
MIN_FUNDING_SPREAD=0.00005
```

## Что НЕ защищает риск-менеджер

1. **Ликвидация при flash crash**: резкое движение на одной бирже может ликвидировать ногу до срабатывания delta stop-loss
2. **Депег стейблкоина**: USDT0 на Ink L2 теоретически может потерять привязку
3. **Smart contract exploit**: риск взлома одной из бирж
4. **Ошибки API**: если биржа вернёт некорректные данные о балансе

**Митигация**: диверсификация между несколькими стратегиями, небольшой % от портфеля.

## Circuit Breaker

Срабатывает после `CIRCUIT_BREAKER_FAILURES` последовательных неудачных ордеров.

Пауза с exponential backoff:
```
1-е срабатывание: пауза 30s
2-е срабатывание: пауза 60s
3-е срабатывание: пауза 120s
...
максимум: 3600s (1 час)
```

После паузы circuit breaker сбрасывается и бот возобновляет сканирование.
При каждом успешном ордере счётчик ошибок сбрасывается.
